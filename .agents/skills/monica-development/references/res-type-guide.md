# Monica result-envelope boundary

Use `Res` or `Res<T>` for Facades and other public boundaries intentionally exposing Monica's envelope. Internal infrastructure services use direct returns and exceptions. The serialized envelope uses `message`, `status`, `metadata`, and, for generic results, `data` under the repository's camelCase policy.

An implicit `T → Res<T>` conversion can return successful data, and a string can represent a failure. The `string` case is special: for a method returning `Res<string>`, use `Res.Ok<string>(value)` for success. `Res.Ok(value)` selects the non-generic `Res.Ok(string hint)` overload and loses `Data`. Use `IsFailed(out error, out data)` at callers; `IsOk` accepts 200 and 201 but does not promise a payload. Declare `Res<T?>` and check the data when absence is allowed.

`metadata.error` is reserved for one `ResultError` contract with stable code, nonempty origin trace, optional logical service/operation, and bounded request field errors. Capture the trace once at the owning boundary. Keep exception text, stack traces, request/response dumps, and call chains in operator diagnostics; public failures get safe application messages. Unexpected defects should reach the host handler. A Facade that deliberately catches an exception logs it under host policy and returns a safe failure. `ResStatus` is the supported HTTP outcome whitelist; express detailed reasons with `ResultErrorCodes` instead of invented statuses.

Use `GetResponse()` (or `GetResponse(controller)`) at HTTP boundaries. `ModuleResultEnvelopeOption.ExposeDiagnosticDetails` controls whether reserved diagnostic metadata may be exposed; ordinary hosts strip it. Configure top-level field names through `monica.AddResultEnvelope().UseResultFieldNames(...)` only when the host needs a different wire convention.

Generated API clients and custom forwarders use `IRemoteCallClient` for the complete exchange. The request factory transfers request ownership, the client is borrowed, caller cancellation propagates, and the call boundary does not retry. Configure `ModuleApiClientOption.CallTimeout` for generated API deadlines. A timeout or downstream 429 does not establish whether a command executed. Remote application failures are preserved only when the envelope and HTTP status agree; transport classification is selected by transport behavior, not message prose. The remote boundary records target identity and correlation for the call chain on both success and failure. See the framework's current implementation for exact diagnostic fields when changing the protocol.
