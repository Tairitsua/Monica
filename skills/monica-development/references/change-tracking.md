# Typed change tracking and replay

`Monica.Framework.ChangeTracking` models accepted changes independently of EF and delivery. Use `ChangeEntry<TEntity, TData, TSource>` with `IChangeData<TEntity>` and `ChangeChain<TEntity, TEntry, TData, TSource>`. The renamed contracts replace `ChangeItem`, `IChangeItemData`, `ChangeItemPropertyAttribute`, and `GenerateChangeItemDataAttribute`; generated data defaults to `<Entity>ChangeDataGen`. Update consumer code and regenerate it together. Existing `DataJson` field names remain application-owned.

An entry's complete `ChangeOrderKey` is `(SortTimeTicks ?? OrderTime.Ticks, HistoricalOrder ?? long.MaxValue, Id)`, with ordinal identity comparison. `OrderTime` retains the original effective time and legacy microsecond adjustment. New equal-time entries sort by stable ID; adding an entry never changes its timestamp or offset. `ShouldReconstruct` compares the complete key, including equal timestamps. Applications assign stable IDs before any repeatable side effect.

Use `ChainJsonParseBridge` for old JSON: version 1 freezes its original list positions in `HistoricalOrder`; version 2 retains explicit ordering metadata. Do not reconstruct a legacy document through the raw `(tracingData, entries)` constructor, which assumes entries already carry their intended ordering. Conversion of production data must verify the legacy projection and rollback flags before adopting the new replay semantics.

Rollback entries contain a nonempty set of target IDs. Targets must already exist when a chain is accepted; missing targets, cycles, and duplicate entry IDs fail. Dependencies, rather than timestamp order, determine whether rollback instructions themselves are active. Multiple active rollback instructions keep a target inactive until all are undone. `RollbackBy` is a derived diagnostic value and is recomputed on load; it is not authoritative persistence. An empty target collection behaves as ordinary change data.

Replay starts from the fixed baseline and applies active normal entries in business order. It does not publish events, query databases, refresh routes, or perform audit writes. `DataJson` replacement invalidates cached typed data; mutations of `Data` require `RefreshDataJson()` before persistence. Treat accepted entry data and order keys as immutable after insertion.

`CreateRollbackAlterItemBySourceId` accepts an optional operation time; it selects known direct and related source targets whose original alteration time precedes that boundary. A retry owner should carry the original operation time across attempts. Omitting it uses the current local time.

The generator includes public settable properties except ignored metadata, `Id`, and `ConcurrencyStamp`; `ChangeEntryProperty` supplies titles or `Ignore = true`, rather than acting as an opt-in marker. Explicitly exclude identity, audit, and independent projections on each application entity. Generated `CopyTrackedState(source, target)` copies the generated field set, including nulls and empty collections, while retaining existing optional navigation objects. If the source navigation is missing, tracked fields reset to a new navigation's defaults. Required owned objects must already exist. Applications normalize child keys and tracked collection identities and preserve custom state outside generated data. Do not map a replayed whole entity onto a live tracked aggregate.

The application owns a transaction covering projection, accepted facts, concurrency checks, and Outbox intents. A later entry can use an incremental apply when its full key exceeds the accepted tail and it is not a rollback; otherwise rebuild from baseline and accepted facts. Persist source references and frozen rollback targets with the entry, without deriving them again during replay. The framework does not impose table counts, database locks, retries, or event sourcing on every consumer.

Behavioral checks: `tests/Test.Monica.Framework/ChangeTracking/ChangeChainOrderingTests.cs` covers equal-time permutations, legacy positions, rollback dependencies, malformed chains, and data-cache invalidation.
