# Request endpoints and execution

The execution-pipeline UI formats its plan-capture timestamp with the shell's shared Clock display policy in `$monica-infra-ui` (`references/time-display.md`); the catalog's captured instant and pipeline behavior are unchanged.

## Transport-independent application calls

`ApplicationService`, `ServiceBase`, `DomainService`, and `IResultRequest` are owned by `Monica.Application.Abstractions`; request validation is in `Monica.Application.Validation`. `AddWebApi()` composes `AddApplication()` for the shared mediator, authorization and DataAnnotations validation path. `AddApplication()` alone publishes no HTTP endpoints. Standard authorization no longer requires a permission-bit enum; use `AddAuthorization<TEnum>` only for that model.

`Monica.Application.Annotations.ApiEndpoint(ApiHttpMethod, route)` declares the application operation and its HTTP mapping in one attribute. Local and HTTP clients share this declaration; carrying HTTP metadata does not publish endpoints. Each `[assembly: ApplicationHost]` combines shared ownership metadata where used with its actual local domain/role implementations to generate its manifest and clients. Receivers come only from local implementations; `AddApplicationModel` validates deployment ownership and `AddApplicationInvocation` routes each operation. Standalone consumers can still use `ApplicationApiGenerationConfig` and optional `WebApiGenerationConfig`. Optional assembly-wide `HttpApiContract` settings customize the shared prefix. See [API generation and registration](../../monica-infra-messaging/references/invocation.md) for configuration, ownership and migration.

Unattributed requests remain internal mediator operations. Local outer calls create operation scopes; nested Local calls join the active operation. Query read-only defaults follow Query semantics, including POST queries; explicit handler transaction metadata wins. MVC binding remains separate from application validation. See application invocation in `$monica-application-ui` (`references/application-invocation.md`) for UI identity and lifecycle rules.

For role-local request contracts outside `PublishedLanguages`, the generator derives the wire domain from the declaring assembly's `ApplicationRole`. An explicit `HttpApiContract.DomainName` takes precedence when retaining an existing wire name. An assembly without role metadata still needs the explicit name; a non-identifier domain also needs a valid explicit generated name. This inference changes no declared HTTP method or route.


Inside the host's `builder.AddMonica(monica => { ... })` callback, `AddAutoControllers(configure?, configureCrud?)` discovers `ControllerBase` types and `ICrudApplicationService` implementations from the configured type-discovery scope, validates CRUD options, registers generated MVC conventions, and maps controllers. It depends on AutoModel, the core controller module, and exception handling; `AddWebApi()` already requires it. Application request contracts own their `[ApiEndpoint]` method, route, and binding metadata. The reference app puts those attributed requests in `Platform.Protocol/PublishedLanguages` and adds that assembly to type discovery. For request naming, controller placement, and endpoint ownership, read `$monica-application-project-unit-development`.

When a controller or generated route is missing, check that its assembly is discovered, that its service shape is eligible, and that its CRUD naming/suffix matches configured conventions before manually adding routes. Invalid CRUD options fail service composition with `OptionsValidationException`. Inspect the generated API description and [Swagger document assignment](api-documentation-and-visibility.md) if the route exists but is missing from the chosen document.

With an application model, generated request receivers require a local implementation and are selected per action from their owning role. An inactive role's action is removed before MVC constructs endpoints, including when the same controller contains methods from other roles. Ordinary included handlers remain callable locally; RunOnRole requests additionally require their role at execution. Remote-only operations do not publish forwarding receivers. CRUD services and hand-written controllers in inactive role assemblies are likewise excluded from ingress. This filtering does not remove unrelated framework controllers.

For a host containing several local domains, configure `AddAutoControllers(configureCrud: options => options.RoutePath = "api/v1/{domain}")`. The literal `{domain}` token expands using the concrete controller assembly's declared role or domain core, yielding routes such as `api/v1/Ordering/order`. It is not a caller-supplied route value or the current host's single domain. An unowned controller using this token fails endpoint composition. Explicit controller Route attributes still override the global prefix. The default prefix remains `api/v1/[controller]` for standalone compatibility.

`AddAutoModel()` registers model snapshots and expression operations. Its optional Web status route is `/auto-model/status` when the common minimal-API switch permits it. `EnableActiveMode` limits AutoModel fields to those marked `AutoField`; most other AutoModel switches control naming, ignored attributes, or diagnostics. Avoid turning on `EnableTitleAsActivateName`: the property is marked obsolete and unimplemented.

The ProjectUnit domain-event tester uses the shared JSON editor in `$monica-infra-ui` (`references/json.md`) for its event draft. Formatting and syntax feedback do not publish events; its explicit Publish command retains the framework serialization, deserialization and dispatch behavior.

ProjectUnit HTTP endpoints follow request-owned metadata and execute through the shared typed execution pipeline. `AddProjectUnits()` owns architecture discovery and requires EventBus; its optional request filter is off unless `EnableRequestFilter` is selected. The pipeline is also used outside HTTP: authorization and execution timing install filtered behaviors for business operations. Do not bypass it with a second ad hoc controller path for the same request contract.

Runtime and source catalogs associate the request from all native generic handler bases: `ApplicationService<TRequest>` has no payload response type, `ApplicationService<TRequest, TResponse>` exposes its payload type, and `CustomApplicationService<TRequest, TResult>` exposes its explicit result type. Concrete project specializations retain this association through their native base. Source analysis contract v7 refreshes cached catalogs to discover native `IRequest<TResponse>` payloads as well as `IResultRequestBase`, matching runtime request-unit discovery for custom application services. The request must remain in the host's discovery scope; classification does not approve the application's architecture.

ProjectUnits includes closed generic event payloads and request contracts referenced by discovered handlers when their generic definitions are also in the discovery scope. Open generic definitions are not catalog units. Each closed type retains its full CLR identity, metadata, and links to its consumers; a missing or excluded contract definition still produces an association warning. Event payloads must implement `IDomainEvent`; application event conventions remain owned by the ProjectUnit development skill.

Declare a transaction override or database selection only with `ExecutionTransactionAttribute` on the concrete handler/action method; the execution descriptor resolves that declaration for every adapter. Use the persistence [transaction contract](../../monica-infra-persistence/references/transactions.md) for defaults, automatic saving, and independent operation scopes.

`AddExecutionPipeline()` can be registered directly when a host needs typed execution without the Web API bundle. `.AddBehavior<TBehavior>(order, descriptorFilter, lifetime)` adds one implementation to the host-owned catalog; filters decide which descriptors receive it. The same behavior type registered twice fails composition, and behavior service registrations are checked for exclusivity. Use `ExecutionPipelineCatalogFacade` to inspect the effective behavior plan when an expected authorization, timing, or custom behavior is absent. Route generation and execution behavior are related but distinct: first confirm endpoint discovery, then confirm the request reaches the pipeline.

For a Web host with a Monica shell, `AddProjectUnitsUI()` exposes the discovered architecture catalog and requires ProjectUnits, localization, and the shell. `AddExecutionPipelineUI()` presents the effective behavior catalog and requires the pipeline, localization, and the shell. These are optional inspection pages; their access policy belongs to `$monica-infra-ui`, and neither page is required for HTTP request execution.

`AddProjectUnitsUI()` registers six independently routed pages in the shell's Monitor → Project Units branch. The original `/project-units` address remains the Overview destination.

Configuration details report Startup values as requiring restart even when their consumers use `IOptionsSnapshot<T>` or `IOptionsMonitor<T>`, or no consumer is discovered. These accessors all return the same frozen Startup object. Managed configuration alone uses accessor-based reload inference; see the configuration unit contract in `$monica-application-project-unit-development` (`references/16-configuration-template.md`).

The catalog’s full-identity dossier is a native modal with a localized visible heading that names its actual dialog role. It uses the shared dialog heading contract in `$monica-ui-development` (`references/blazor-best-practices.md#14-native-dialog-headings`); keyboard focus and dismissal remain native. Opening the dossier reads captured evidence and does not execute the selected unit.

Each page has its own shell/search name and title. The shared workspace links are real routes, so direct navigation and browser Back/Forward identify the task. Leaving a page disposes its local view; returning creates a fresh view with newly loaded data, local filters, selection, graph, or draft. No cross-route page session, storage, or polling is introduced. Host-owned catalog data remains independent of those page lifetimes. The route split adds no backend API endpoint or access policy; existing facade operations and host configuration retain their contracts.

Refresh reads the host's discovered catalog rather than rescanning assemblies or executing units. The catalog presents Title and full Key together, retaining the complete identity for search and inspection. Its full-key sort control cycles unsorted → ascending → descending → unsorted through the native grid's multiple-sort API; removing the Key sort preserves any other active sort. Name sorting retains the native grid's multiple-sort behavior. The four context coverage dimensions have independent covered/total denominators and an undefined percentage for an empty catalog; they are not runtime health or a combined readiness score. The relationship workspace's connected-component scope traverses both dependency directions and overrides ordinary filters until cleared. Enum positions are enumeration-order indices, not numeric enum values.

Graph cursor actions retain the exact admitted unit and full Key across asynchronous work. Each right-click establishes a distinct opening, including repeated clicks on the same unit at the same coordinates; late completion cannot close a replacement menu or render into a retired graph. The native unit ledger supplies equivalent actions, and copying the full name preserves the complete Key. Custom graph integrations follow the shared cursor-menu contract in `$monica-infra-ui` (`references/shell-and-access.md`) for opening revisions, page coordinates, native focus and lifetime ownership.

Domain-event descriptors from `ProjectUnitsFacade.GetDomainEventsAsync()` expose `ProjectUnitDomainEventInfo.EventKey`, the exact full CLR identity used for publication. Pass that value to `PublishDomainEventAsync(eventKey, payload)` or the existing `/framework/units/domain-event/{eventKey}/publish` route; do not derive it from the friendly title. Full identity is resolved before legacy short names, so equal short names in different namespaces remain independently publishable. Legacy short keys work only when unique across the catalog; ambiguous names are rejected without publishing, and `IProjectUnitCatalog.FindByName` returns null. Equal short names in distinct domains or closed generic constructions are valid and do not themselves produce discovery errors. Selecting a descriptor only creates an editable representative payload; Publish deserializes the supplied JSON with this host's serializer and performs a real distributed EventBus operation. It is not a simulated preview, and page disposal does not cancel a publication already dispatched to the bus. Select the host's intended provider explicitly as described in [Web composition](web-composition.md).

`ProjectUnitsFacade.GetRequestFilterStateAsync()` reads a detached host-local snapshot containing `IsAvailable` and `DisabledPaths`. An unavailable service differs from an available service whose disabled-path set is empty. Availability establishes service registration only: it does not prove middleware attachment, endpoint authorization, or universal request access. `EnableRequestFilter` defaults to false; when enabled, `UseMonica()` attaches the module's middleware. Paths are ordinal and case-sensitive, duplicates are idempotent, and enabling one path changes the actual host-local filter. `ManageRequestFilterAsync(urls, disable)` retains its existing mutation/read contract and returns an empty list when no service is registered; use the new read method when that distinction matters. The UI names each path action explicitly and disables mutation controls for an unavailable service. Neither facade introduces a new permission policy or changes endpoint exposure.

An event without a public parameterless constructor, such as a positional record, remains in the event catalog with a null representative `Structure`; enter its actual JSON payload when publishing. Sample construction does not invent constructor arguments. Nested abstract or constructor-bound types and recursive references are represented by null so one valid event shape does not prevent inspecting the rest of the catalog.

The `/execution-pipeline` page distinguishes observed plans from the complete candidate-registration catalog. Snapshot queries inspect cached metadata; they do not execute an operation or construct missing plans merely to populate the page. Ready/Faulted and plan timestamps describe chain materialization, not a business invocation result or duration. The selected plan shows actual outer-to-inner positions and closed behavior types separately from configured registration order and registered types. Behaviors can short-circuit the terminal handler. A successfully materialized plan with no behaviors still has a terminal handler; missing behavior metadata on a faulted plan does not establish a terminal-only chain. An excluded candidate has no recorded per-plan exclusion reason. Refresh preserves filters and reconciles selection by stable plan ID. Exact expandable/copyable diagnostics retain full identifiers and available policy, source, lifetime and fault evidence rather than replacing them with abbreviated display names.
