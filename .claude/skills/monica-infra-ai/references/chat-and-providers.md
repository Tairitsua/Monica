# Chat, providers, and history

Register `AddAI()` for code-driven chat, then add a real provider with `AddOpenAIProvider(...)`, `AddAnthropicProvider(...)`, or `AddProvider<TProvider>(...)`. `AddFakeProvider(...)` supports development. `AddAIUI()` adds chat and management pages plus knowledge-base inventory, skill, MCP, localization, and shell dependencies, but does not choose provider credentials, models, or deployment storage and identity. Its pages are an application interface; code callers use `ChatFacade` and the other facades directly. Register modules inside one `builder.AddMonica(...)` callback; a Web host completes Monica with `app.UseMonica()` and `app.MapMonica()`.

The packaged chat page fills the shell's available content height and owns its internal scrolling. Layout follows the actual available parent and chat-content sizes, including short heights, in both Sidebar and Topbar layouts. History uses a 272px persistent drawer at a wide owner and a temporary drawer bounded by `min(304px, calc(100% - 48px))` at a compact owner. Temporary history starts closed, closes after successful conversation selection or creation, and keeps its backdrop inside the content region, leaving application navigation available. The wide drawer retains its open preference across size changes. When embedding or customizing chat, provide a bounded parent height with `min-height: 0`; keep the drawer page-relative with `MudDrawerContainer` and `Fixed="false"`, and keep its overlay local. Derive interaction breakpoints from usable owner space rather than the browser viewport, and preserve the temporary drawer's focus and dismissal lifecycle. The containment contract is implemented by `Monica.AI.UI/Pages/ChatPage.razor`, its isolated stylesheet and layout observer; shell hosting belongs to UI shell and access in `$monica-infra-ui` (`references/shell-and-access.md`).

```csharp
builder.AddMonica(monica =>
{
    monica.AddAI()
        .AddOpenAIProvider(options =>
        {
            options.ApiKey = builder.Configuration["AI:ApiKey"] ?? "";
            options.SupportedModels = ["gpt-4o-mini"];
        });
});
```

The host owns secret loading and model choice. `gpt-4o-mini` is in the reserved model catalog; register a custom model with `AddModel(...)` before naming it in `SupportedModels`, or define provider-scoped model metadata when providers use the same name differently. Give providers stable IDs if persisted sessions must continue to resolve them. Code-defined provider settings can be overridden by persisted host settings. Invalid OpenAI or Anthropic keys/initialization yield visible but disabled providers with configuration errors, so inspect `ProviderFacade` or `ChatFacade.GetProviders()` before starting a session. Invalid provider or model configuration found at startup also disables the affected provider with its reasons shown on the provider management page (the default `Disable` mode); set `ModuleAIOption.ConfigurationValidationMode = Throw` to fail startup instead. Runtime settings edits always validate strictly in both modes.

`AddAIUI()` links three sibling administration destinations: providers and models at `/ai-providers`, Skills at `/ai/capabilities`, and MCP at `/ai/capabilities/mcp`. The existing capability route defaults to Skills. Each destination uses native routing; moving between Skills and MCP retires the previous page, canceling and draining its admitted work without disposing borrowed host facades. These pages manage host-wide settings; chat history and conversation instructions keep their own user/workspace scope. Hosts must apply their operational authorization policy before exposing provider configuration methods or the management UI. Page visibility and disabled controls are not authorization checks. See [runtime skills](runtime-skills.md) and [MCP](mcp.md) for capability and connection management.

Use `AIConfigurationFacade.GetAsync()` to obtain credential-free effective values and their complete settings revision. `UpsertProviderAsync`, `RemoveProviderAsync`, and `ResetProviderAsync` require that captured `expectedRevision`. Retain the revision from when the draft opened; a later refresh must not attach a newer revision to an older complete draft. A stale write fails without applying the mutation. The packaged editor retains its draft and diagnostic for review rather than silently overwriting or retrying. Saving changes the provider used by new requests; running requests retain their captured settings. A configured Enabled flag is intent, and does not prove valid initialization or successful authentication.

Provider writes replace one complete override. Preserve values outside a customized form, including Responses history mode, prompt-cache settings, organization, and project, by copying the original `AIProviderConfiguration`. Provider IDs are stable, and model identity is scoped to its provider ID; duplicate model IDs within one provider are rejected case-insensitively. Choosing a default provider is one atomic settings mutation. Only a configured Chat model may be its default model; a null `DefaultModel` uses the first configured Chat model. Code-defined providers can be disabled, but cannot be deleted. `ResetProviderAsync` removes the entire persisted override and restores every code baseline value, including its credential; it is not a reset of only the visible fields. Runtime-created providers have no code baseline and may be deleted. Host-supplied custom providers are outside this runtime-settings inventory and cannot be replaced through it.

Provider keys are supplied separately from configuration, protected by the host's data-protection key ring, and absent from returned snapshots. Keep the host key ring durable when persisted credentials must survive deployment. A null or empty key preserves the existing credential. `clearApiKey: true` explicitly removes it and prevents fallback to the code key; supplying and clearing a key in one write fails. The UI exposes credential presence and a password input, and clears its transient key when the dialog retires. Resetting a code override can restore the code credential, so reset and explicit clear have different effects.

The model editor accepts exact token counts and binary K/M shorthand (`256K` = 262,144; `1M` = 1,048,576), shows the exact value, and stores integer limits. Empty Chat context uses the 256K planning fallback and remains unverified metadata; empty Embedding context remains unknown. Unknown output limits remain unknown. Code callers can use `TokenQuantity.TryParse` for the same input contract. See `tests/Test.Monica.AI/Configuration/TokenQuantityTests.cs` for fractions, overflow, and lossless formatting.

Capability checkboxes preserve supported, unsupported, and unknown separately. Native document support is independent of text extraction. Select only endpoint-supported reasoning levels; Auto omits a default effort override. Advanced mappings retain custom level IDs and provider values. Anthropic thinking budgets must be at least 1,024 tokens, below configured maximum output when supplied, and incompatible with a `none` provider mapping. OpenAI saves omit Anthropic-only budgets. Turning reasoning explicitly off clears its levels and default. The editor's Reset restores its initial model draft, and nested model edits stay local until the containing provider is saved.

`AIConfigurationFacade.DiscoverModelsAsync` lists remote model metadata without saving it or testing inference. `DiscoverDraftModelsAsync` uses captured unsaved connection settings and a transient key without publishing the provider; `useSavedApiKey` explicitly permits the matching saved credential when no draft key is supplied. Cancel obsolete work and discard results when connection settings change. Importing discovered models changes only the open draft. Metadata merge fills unknown fields without replacing explicit choices or custom reasoning mappings. Built-in catalog templates apply only to trusted official endpoints; a matching model ID on a custom proxy does not prove capacity or capability. Monica does not synchronize ZCode's recommendation catalog.

The administration connection test uses `AIConfigurationFacade.TestProviderAsync`, which lists models without inference billing. A listing failure does not prove that inference is unusable. `TestModelAsync` deliberately sends a small text inference request with maximum output 16 and may incur usage charges; the packaged UI offers it only for configured Chat models and never runs it automatically during load or discovery. `ProviderFacade.TestProviderAsync` is a different inference check, so do not substitute it while promising a metadata-only test.

The provider-wide `SystemPrompt` is a host default. Editing instructions in an existing conversation changes that conversation's next request through its session owner; it does not save provider configuration or rewrite a running request.

Keep the Microsoft.Extensions.AI OpenAI adapter compatible with the OpenAI SDK: adapter 10.10.1 targets OpenAI 2.14.0. Adapter 10.10.0 references a Responses MCP approval type renamed in SDK 2.14.0 and can fail with `TypeLoadException`; upgrading only the SDK is insufficient. The production provider construction regression test covers both Chat and Responses API surfaces.

Resolve scoped `ChatFacade` from the caller's DI scope. Create a session, then consume the ordered `Res<ChatStreamEvent>` stream. Text arrives as `ChatTextDeltaEvent`; tool, reasoning, context, and completion events have separate types. A `ChatCompletedEvent` with `AwaitingApproval` means the run has paused: present the request and call `ContinueApprovalAsync(...)` with the decision, or `CancelAsync(...)`. `EditMessageAsync`, `RetryMessageAsync`, `UpdateSettings`, and `UpdateRuntimeContext` apply to subsequent execution, not a turn already in flight. Dispose the session when its owner is done.

```csharp
var created = await chat.CreateSessionAsync(ct: cancellationToken);
if (created.IsFailed(out var createError, out var session))
    throw new InvalidOperationException(createError.Message);

await using (session)
{
    await foreach (var next in chat.SendMessageStreamingAsync(session, "Summarize the order", cancellationToken))
    {
        if (next.IsFailed(out var streamError, out var update))
            throw new InvalidOperationException(streamError.Message);
        if (update is ChatTextDeltaEvent delta)
            Console.Write(delta.Text);
    }
}
```

Direct facade consumers own history writes. `ChatHistoryFacade.GetCatalogAsync()` gives the current catalog revision; pass it to `SaveSessionAsync(session, expectedRevision)` after a turn and inspect the returned `ChatHistoryWriteResult.IsPersisted`, `IsConflict`, and `FailureReason`. A stale revision applies no mutation and should trigger a catalog/session refresh before retry. `LoadSessionAsync` restores a transcript lazily; `SetPinnedAsync`, `SetArchivedAsync`, and `DeleteArchivedSessionsAsync` manage the catalog. The packaged AI UI manages this lifecycle for its own sessions.

The packaged composer keeps unsent text and caret position separately for each conversation during the current page visit. Switching conversations restores the matching draft, and an accepted send clears only its originating draft. These drafts are transient component state: leaving or reloading the page does not restore them from history or browser storage. Staged attachments have their own durable upload and discard lifecycle; text-draft retention does not imply attachment retention across a conversation switch.

A failed history catalog read remains a write barrier until an explicit reload succeeds. Preserve the diagnostic and existing in-memory state; do not treat an unreadable catalog as empty history, create a replacement conversation automatically, or resume automatic saves after an unrelated render or provider refresh. The packaged reload obtains confirmation before replacing local session copies, and a failed reload retains the barrier. Revision conflicts likewise require explicit recovery before further edits can write history.

While generation, upload, a history update, or a settings command owns the page, its state owner rejects competing conversation selection, creation, and archive mutations as well as new execution commands. Disabled controls must agree with those handler checks. Stop has separate admission and remains available during generation; it requests cancellation while the admitted operation owns drainage and terminal history persistence. Keep automatic execution checkpoints with that operation rather than routing them through competing catalog-action admission. See `ChatPageState`, its session/message partials, `ChatSessionWorkspace`, and `ChatInputArea` for these ownership boundaries.

For an image or document input, persist an active session first, then use `ChatAttachmentFacade.UploadAsync(sessionId, fileName, mediaType, stream)` in the same trusted partition. Send its returned `ChatAttachmentReference` as `ChatContentPart.FromAttachment(...)` inside a `ChatUserInput`; the plain-string overload is for text only. The caller owns the upload stream. `ModuleAIOption.MaxChatAttachmentBytes` defaults to 20 MiB and `MaxExtractedDocumentCharacters` to 200,000; an overlong document is rejected rather than truncated. `UseChatAttachmentStore<TStore>()` replaces the file attachment store when host storage requires it.

The default `FileChatHistoryProvider` stores history under `ModuleAIOption.StorageRootPath`, `monica_data/ai` relative to the process working directory. Set an absolute writable path when working directories vary. `UseChatHistoryProvider<TProvider,TPartitionResolver>()` replaces it; custom providers must isolate partitions and protect persisted agent state. `IChatUserIdentityAccessor` supplies trusted identity: the AI UI uses its authenticated Blazor circuit principal, while unauthenticated hosts share one workspace partition. Browser-generated IDs are not identities. `ModuleAIOption.WorkspaceId` defaults to `default` and separates host workspaces using the same storage.

`AddAIEndpoints().MapAIEndpoints()` optionally exposes provider discovery at `/ai/providers` on a Web host; it is not a chat streaming API.
