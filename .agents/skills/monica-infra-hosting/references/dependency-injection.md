# Conventional dependency injection and decoration

`monica.AddDependencyInjection()` opts the host into service registration by convention. Concrete classes implementing `ITransientDependency`, `IScopedDependency`, or `ISingletonDependency`, or marked with `DependencyAttribute`, are candidates only when their assembly is in the configured type-discovery scope. Put the marker on an application service with the intended lifetime, then include its assembly through `ConfigureTypeDiscovery(...)` inside the same `AddMonica(...)` callback. Monica also registers `ICachedServiceProvider`; this is a module service, not a reason to bypass ordinary scoped DI.

If a marked service is missing, check the assembly selection, whether the class is concrete, and the marker or attribute before manually adding a duplicate descriptor. `monica.AddDependencyInjection().EnableAutoRegistrationDiagnostics()` captures a startup snapshot and declares the hosted-service dependency for that capture. `EnableAutoRegistrationLogging()` separately controls per-type startup logs; it is disabled by default even when the snapshot is enabled. Inspect `DependencyInjectionDiagnosticsFacade` or the startup output for registration decisions.

There is no current production `ModuleDynamicProxy` or `AddDynamicProxy()` registration in Monica DI/Core. The remaining public interface-proxy decorator extension, `IServiceCollection.DecorateInterfaceProxy<TInterface,TDecorator>()`, is in `Monica.Experimental`, which is included in the solution but is not a Monica module. It decorates matching registered interfaces; the non-`Try` form throws `DecorationException` when none is registered, while `TryDecorateInterfaceProxy` returns `false`. Treat this as an explicit experimental DI choice, not an automatic effect of `AddDependencyInjection()`. For execution-wide behavior use the typed execution pipeline; for a local wrapper, choose decoration after checking the service lifetime and interface contract.

Verify discovery and diagnostics against `Monica.DependencyInjection/Modules/ModuleDependencyInjection.cs` and `Monica.DependencyInjection/Services/ConventionalRegistrar.cs`. For graph and host lifecycle, read [host composition](host-composition.md); for module strategy design and type discovery internals, read `$monica-development`.
